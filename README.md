# Агрегатор вакансий

Курсовая работа: «Разработка системы агрегации вакансий с применением методов нечёткой дедупликации и асинхронной обработки данных».

## О чём работа

Одна и та же вакансия публикуется сразу на нескольких площадках: сайтах поиска работы, в Telegram-каналах, на сайтах компаний. Система автоматически собирает вакансии из нескольких источников, отбирает подходящие по заданным критериям и убирает повторы.

## Основные задачи

**Нечёткая дедупликация.** Нужно определить, что две записи из разных источников описывают одну вакансию, хотя точного совпадения нет: «Junior Python Developer» и «Младший разработчик Python», разные написания компании, сокращённое или переформулированное описание. Сравниваются три подхода:

- редакционное расстояние (расстояние Левенштейна);
- коэффициент Жаккара и его быстрое приближение (MinHash);
- векторные представления текстов и косинусное сходство.

Критерии сравнения — точность (верно найденные дубликаты и ошибочные совпадения) и скорость на растущем объёме данных.

**Асинхронная обработка.** Источники опрашиваются параллельно, сбой одного не останавливает остальные. Эффект оценивается экспериментально: время последовательного и асинхронного сбора.

## Инструменты

Python, Django, asyncio и httpx для сбора, BeautifulSoup для разбора страниц. База данных — SQLite по умолчанию, PostgreSQL через переменные окружения.

## Источники

| Источник | Что собирается | Особенности |
|---|---|---|
| rabota.by | поиск по запросу | страницы поиска, 20 вакансий на страницу |
| belmeta.com | поиск по запросу | агрегатор: часть вакансий повторяет rabota.by |
| jobs.devby.io | весь список IT-вакансий | поиска по тексту нет |
| myjob.by | раздел «IT, Интернет, Телеком» | поиска по тексту нет |
| Greenhouse | вакансии компании в Беларуси | JSON сервиса найма: ISsoft, Coherent Solutions, Tripledot Studios |
| Lever | вакансии компании в Беларуси | JSON сервиса найма: IDT, Satellite Innovations |

Новый источник — это класс-наследник `Source` с двумя методами: `page_url` (адрес страницы списка) и `parse` (разбор ответа). Если полное описание лежит на странице вакансии, добавляется `parse_detail`. После этого источник достаточно вписать в `default_sources`. Компания на Greenhouse или Lever подключается одной строкой без нового кода.

## Дедупликация

Методы лежат в `apps/vacancies/services/dedup/` и реализованы без сторонних библиотек:

| Модуль | Метод | Что сравнивает |
|---|---|---|
| `levenshtein.py` | редакционное расстояние | строку «название + компания» |
| `jaccard.py` | коэффициент Жаккара | тройки символов названия и компании либо пары слов всего текста |
| `minhash.py` | MinHash и отбор кандидатов через LSH | сигнатуры множеств пар слов |
| `vectors.py` | TF-IDF и косинусное сходство | векторы слов |

Эталон для оценки берётся из самих данных: Belmeta — агрегатор, и для части вакансий она указывает адрес первоисточника на rabota.by. Пара «вакансия Belmeta — её первоисточник» считается дубликатом, все остальные пары — нет. Команда `evaluate_dedup` для каждого метода подбирает порог с наибольшим F1 и показывает точность, полноту и время работы.

## Запуск

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python manage.py migrate

# асинхронный сбор, по две страницы с каждого источника, с полными описаниями
.venv\Scripts\python manage.py collect --query python --pages 2 --details

# то же по очереди и без записи в базу — для сравнения времени
.venv\Scripts\python manage.py collect --query python --pages 2 --sequential --no-save

# сравнение методов дедупликации на собранных данных
.venv\Scripts\python manage.py evaluate_dedup

# админка: http://127.0.0.1:8000/admin/
.venv\Scripts\python manage.py createsuperuser
.venv\Scripts\python manage.py runserver

# тесты
.venv\Scripts\python -m pytest
```

## Настройки

Настройки читаются из переменных окружения; их можно записать в файл `.env` рядом с `manage.py`.

| Переменная | Назначение |
|---|---|
| `DJANGO_SETTINGS_MODULE` | `config.settings.development` (по умолчанию) или `config.settings.production` |
| `DJANGO_SECRET_KEY` | секретный ключ Django; на сервере обязателен |
| `DJANGO_ALLOWED_HOSTS` | адреса сайта через запятую; на сервере обязателен |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `DB_HOST`, `DB_PORT` | подключение к PostgreSQL; если `POSTGRES_DB` не задана, используется SQLite |

## Структура

```
manage.py
config/
    settings/            base.py, development.py, production.py
    urls.py
apps/
    accounts/            пользователи
    vacancies/
        models.py        вакансия в базе
        admin.py
        services/
            sources/     по модулю на источник
            collector.py опрос источников: асинхронный и последовательный
            storage.py   запись собранного в базу
            schemas.py   вакансия в том виде, в каком её отдал источник
            dedup/       методы сравнения вакансий и их оценка
        management/commands/
            collect.py          сбор вакансий
            evaluate_dedup.py   сравнение методов дедупликации
tests/
    fixtures/            сохранённые фрагменты страниц и ответов для тестов
```
