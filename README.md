# Агрегатор вакансий

Курсовая работа: «Разработка системы агрегации вакансий с применением методов нечёткой дедупликации и асинхронной обработки данных».

## О чём работа

Одна и та же вакансия публикуется сразу на нескольких площадках: сайтах поиска работы, в Telegram-каналах, на сайтах компаний. Система автоматически собирает вакансии из нескольких источников, отбирает подходящие по заданным критериям и убирает повторы.

## Основные задачи

**Нечёткая дедупликация.** Нужно определить, что две записи из разных источников описывают одну вакансию, хотя точного совпадения нет: «Junior Python Developer» и «Младший разработчик Python», разные написания компании, сокращённое или переформулированное описание. Сравниваются три подхода:

- редакционное расстояние (расстояние Левенштейна);
- коэффициент Жаккара и его быстрое приближение (MinHash);
- векторные представления текстов и косинусное сходство.

Критерии сравнения — точность (верно найденные дубликаты и ошибочные совпадения) и скорость на растущем объёме данных.

**Асинхронная обработка.** Источники опрашиваются параллельно, сбой одного не останавливает остальные. Эффект оценивается экспериментально: время последовательного и асинхронного сбора.

## Инструменты

Python, Django, asyncio и httpx для сбора, BeautifulSoup для разбора страниц. База данных — SQLite по умолчанию, PostgreSQL через переменные окружения.

## Источники

| Источник | Что собирается | Особенности |
|---|---|---|
| rabota.by | поиск по запросу | страницы поиска, 20 вакансий на страницу; при частых запросах показывает проверку «я не робот», поэтому страницы вакансий загружаются по одной с паузой |
| belmeta.com | поиск по запросу | агрегатор: часть вакансий повторяет rabota.by |
| jobs.devby.io | весь список IT-вакансий | поиска по тексту нет |
| myjob.by | раздел «IT, Интернет, Телеком» | поиска по тексту нет |
| Greenhouse | вакансии компании в Беларуси | JSON сервиса найма: ISsoft, Coherent Solutions, Tripledot Studios |
| Lever | вакансии компании в Беларуси | JSON сервиса найма: IDT, Satellite Innovations |

Страница вакансии запрашивается один раз: при следующих сборах уже загруженные описания не перезапрашиваются. Если сайт показал проверку «я не робот», сбор описаний с него останавливается до следующего запуска, а в отчёте команды видно, сколько вакансий осталось без описания и почему.

Новый источник — это класс-наследник `Source` с двумя методами: `page_url` (адрес страницы списка) и `parse` (разбор ответа). Если полное описание лежит на странице вакансии, добавляется `parse_detail`. После этого источник достаточно вписать в `default_sources`. Компания на Greenhouse или Lever подключается одной строкой без нового кода.

## Дедупликация

Методы лежат в `apps/vacancies/services/dedup/` и реализованы без сторонних библиотек:

| Модуль | Метод | Что сравнивает |
|---|---|---|
| `levenshtein.py` | редакционное расстояние | строку «название + компания» |
| `jaccard.py` | коэффициент Жаккара | тройки символов названия и компании либо пары слов всего текста |
| `minhash.py` | MinHash и отбор кандидатов через LSH | сигнатуры множеств пар слов |
| `vectors.py` | TF-IDF и косинусное сходство | векторы слов |

Эталон для оценки берётся из самих данных: Belmeta — агрегатор, и для части вакансий она указывает адрес первоисточника на rabota.by. Пара «вакансия Belmeta — её первоисточник» считается дубликатом, все остальные пары — нет. Команда `evaluate_dedup` для каждого метода подбирает порог с наибольшим F1 и показывает точность, полноту и время работы.

На сайте дубликаты объединяются автоматически после каждого сбора (`services/dedup/pipeline.py`). Две записи из разных источников считаются одной вакансией, если агрегатор сам сослался на первоисточник либо совпали компания, город и название (похожесть названий не ниже 0,8). В группе остаётся одна основная запись — первоисточник с самым полным описанием, остальные показываются как «также опубликовано на…».

## API

Сервер отдаёт данные в формате JSON по адресам `/api/v1/…`. Читать вакансии можно без входа; избранное и сохранённые поиски требуют токен в заголовке `Authorization: Bearer <access>`.

| Запрос | Назначение |
|---|---|
| `GET /api/v1/vacancies/` | список вакансий без дубликатов, по 20 на страницу (`page`, `page_size`) |
| `GET /api/v1/vacancies/{id}/` | вакансия с полным описанием |
| `GET /api/v1/filters/` | источники и города с числом вакансий — для выпадающих списков |
| `POST /api/v1/auth/users/` | регистрация: `username`, `email`, `password` |
| `POST /api/v1/auth/jwt/create/` | вход: по `username` и `password` выдаёт токены `access` и `refresh` |
| `POST /api/v1/auth/jwt/refresh/` | новый `access` по `refresh` |
| `GET /api/v1/auth/users/me/` | профиль текущего пользователя |
| `POST`, `DELETE /api/v1/vacancies/{id}/favorite/` | добавить в избранное, убрать из избранного |
| `GET /api/v1/favorites/` | избранные вакансии |
| `GET`, `POST /api/v1/searches/`, `PATCH`, `DELETE /api/v1/searches/{id}/` | сохранённые критерии отбора: `name`, `query`, `city`, `source` |

Параметры списка вакансий: `q` — слова для поиска по названию, компании и описанию (должны встретиться все), `city`, `source`, `has_salary=true|false`, `ordering=first_seen|-first_seen|last_seen|-last_seen`.

У каждой вакансии в списке есть поле `sources` — все площадки, где она опубликована, со ссылками, и `is_favorite`.

## Фронтенд

Интерфейс — отдельное приложение на React в папке `frontend/` (сборка Vite). Экраны: список вакансий с поиском и отбором, страница вакансии, избранное, вход и регистрация. Критерии отбора хранятся в адресе страницы, поэтому ссылкой на выборку можно поделиться; вошедший пользователь может сохранить их и вернуться к выборке одним нажатием. Вёрстка рассчитана на телефон и компьютер.

```
cd frontend
npm install

# разработка: http://localhost:5173, запросы к API уходят на локальный сервер Django
npm run dev

# сборка в frontend/dist — после неё сайт целиком отдаёт Django
npm run build
```

Собранный фронтенд сервер раздаёт сам: файлы — как статику, а на любой адрес, кроме `/api/` и `/admin/`, отвечает страницей приложения. После новой сборки сервер нужно перезапустить.

## Запуск

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python manage.py migrate

# асинхронный сбор, по две страницы с каждого источника, с полными описаниями
.venv\Scripts\python manage.py collect --query python --pages 2 --details

# сбор по всем запросам из настройки COLLECT_QUERIES — эту команду запускают по расписанию
.venv\Scripts\python manage.py collect --pages 3 --details

# заново разметить дубликаты в базе
.venv\Scripts\python manage.py deduplicate

# то же по очереди и без записи в базу — для сравнения времени
.venv\Scripts\python manage.py collect --query python --pages 2 --sequential --no-save

# сравнение методов дедупликации на собранных данных
.venv\Scripts\python manage.py evaluate_dedup

# сайт: http://127.0.0.1:8000/, админка: http://127.0.0.1:8000/admin/
.venv\Scripts\python manage.py createsuperuser
.venv\Scripts\python manage.py runserver

# запуск для постоянной работы (настройки сервера, переменные окружения обязательны)
set DJANGO_SETTINGS_MODULE=config.settings.production
.venv\Scripts\python manage.py collectstatic --noinput
.venv\Scripts\waitress-serve --listen=127.0.0.1:8000 config.wsgi:application

# тесты
.venv\Scripts\python -m pytest
```

## Настройки

Настройки читаются из переменных окружения; их можно записать в файл `.env` рядом с `manage.py`.

| Переменная | Назначение |
|---|---|
| `DJANGO_SETTINGS_MODULE` | `config.settings.development` (по умолчанию) или `config.settings.production` |
| `DJANGO_SECRET_KEY` | секретный ключ Django; на сервере обязателен |
| `DJANGO_ALLOWED_HOSTS` | адреса сайта через запятую; на сервере обязателен |
| `CORS_ALLOWED_ORIGINS` | адреса фронтенда через запятую, которым разрешено обращаться к API |
| `COLLECT_QUERIES` | поисковые запросы для сбора по расписанию, через запятую |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `DB_HOST`, `DB_PORT` | подключение к PostgreSQL; если `POSTGRES_DB` не задана, используется SQLite |

## Структура

```
manage.py
config/
    settings/            base.py, development.py, production.py
    urls.py
apps/
    accounts/            пользователи
    api/                 serializers.py, filters.py, views.py, urls.py
    vacancies/
        models.py        вакансия, избранное, сохранённый поиск
        admin.py
        services/
            sources/     по модулю на источник
            collector.py опрос источников: асинхронный и последовательный
            storage.py   запись собранного в базу
            schemas.py   вакансия в том виде, в каком её отдал источник
            dedup/       методы сравнения вакансий и их оценка
        management/commands/
            collect.py          сбор вакансий и разметка дубликатов
            deduplicate.py      повторная разметка дубликатов
            evaluate_dedup.py   сравнение методов дедупликации
frontend/
    src/
        components/      по папке на компонент: разметка .jsx и стили .module.css
        contexts/        AuthContext.jsx — текущий пользователь, вход и выход
        utils/           api.js — запросы к серверу, format.js — подписи и даты
tests/
    fixtures/            сохранённые фрагменты страниц и ответов для тестов
```
